- 단계: ① Flutter Web 개발·내부 테스트 → ② 웹 베타 테스트 → ③ Android·iOS 빌드와 실기기 검증 → ④ 스토어 출시. ②의 배포 위치는 GitHub Pages(`https://magician-park.github.io/FarmCargo/`)로 정했다. GitHub Pages는 정적 파일만 제공하므로 서버·DB가 필요한 기능을 실제로 쓰는 베타 테스트는 별도 서버를 정한 뒤에 가능하다. ②의 대상·기간과 ③·④의 일정은 아직 정하지 않았다.
- 웹에서 통과한 것이 앱에서도 동작한다고 보장하지 않는다. 카메라·사진·위치·푸시·권한·파일 저장·보안 저장소 같은 기능은 앱 단계에서 다시 검증한다.
- 아래의 ‘앱’은 제품 요구사항을 지칭한다. 실제 서버·DB가 없는 동작은 합성 데이터·시연으로 구분한다.
- 공통 규칙의 기준은 저장소 루트 [AGENTS.md](../../AGENTS.md)다.

## 1. 서비스 정의와 범위

팜카고는 화주가 올린 운송 일거리를 사업자·지역 인증 절차를 거친 차주가 선택하여 운행하도록 연결하는 운송 알선 앱이다.

- 화주 가치: 운송에 신경을 덜 쓰게 해서, 공장주와의 커뮤니케이션에 더 집중할 수 있도록 업무 부담을 덜어준다.
- 차주 가치: 안정적인 일감과, 동선 최소화·최적화로 운송 부가 비용(톨비·기름값 등)을 줄이고 이득을 키우는 것을 목표로 한다. 차주가 원하는 동선의 일감을 고를 수 있게 한다. 자동 경로 최적화의 구현 방식과 절감액은 아직 정하지 않았다.
- 초기 기능: **화주·차주 입력 → DB 저장 → 화주 간 일감 비공개 → 게시글 형식 일감 목록 → 차주 선택·운행**.
- 화주 홈은 배차 작성과 나의 배차로 연결되며, 본인 일감을 확인·수정하는 방향이다.
- 차주 앱은 홈과 일감 목록 탭으로 나눈다. 홈에는 추천 맞춤 오더를 두고, **일감 목록은 별도 탭에서 게시글 형식으로 쭉 나열**한다(사용자 결정 2026-11-04). 추천 기준(별점 혜택·동선 반영 여부)은 아직 정하지 않았다.
- 운영·인증·증빙·제재·혜택은 확인된 요구로 관리하되 세부 방식과 구현 순서는 구체화해야 한다. 운영에는 변수·문제 발생 시 고객센터(전화·카카오톡)가 해당 화주·차주에게 전화로 전후 사실을 확인하고 민원을 처리하는 방식이 포함된다.
- 서비스 AI(OCR 포함)·자주 쓰는 품목 선택지는 기본 틀 구현 뒤 검토한다. 개발 도구로서의 AI 사용과 구분한다. 가입 서류의 사진 기반 자동 입력은 초안에 있으나 도입 시기는 미정이다(D08).
- 장기 공장·창고 확장: **공장의 원료 발주 → 화주 원료 접수·창고 발주 명령 → 운영 측 조달 → 운송 연결**. 실제 앱 기능·조달 책임·시기는 추후 결정한다.

## 3. 가입·로그인 초안(D15·D16)

옵시디언 `14 회원가입과 인증`의 ‘10/31 작성한 회원가입 절차 초안’을 구현 기준으로 옮겼다. 더 운반 영상에서 관찰한 절차와 구분한다. 구현 상태는 Flutter 데모(샘플 데이터·시연) 기준이다.

| 단계 | 초안 | Flutter 데모 구현 상태 |
|---|---|---|
| 최초 진입 | 이용 권한 허용 → 로그인·회원가입 로비 | 구현. 카메라·사진·위치·알림·전화 5종을 안내(사용자 결정 2026-11-04). 사유 문구는 임시이며 실제 권한 요청은 하지 않음 |

### 차주 회원가입 흐름 — 사용자 결정 2026-11-04(2차)

사용자가 직접 다시 설명한 차주 가입 과정이다. 위 표의 이전 차주 초안을 대체한다. Flutter 앱에는 아직 반영하지 않았다.

1. **회원가입 버튼** → **가입 조건 안내 창**(사용자에게 확인하라는 안내):
   - ① 개별화물 자동차 운송사업자: 일반 카고(25톤) / 트랙터(추레라)(25톤) / 워킹 덤프(워킹카)(25톤) / 덤프트럭(25톤) / 기타

   - ③ 필수 제출 서류: 사업자등록증, 통장 사본, 운전면허증
2. **휴대폰 번호 입력** → 문자 인증번호(유효 시간 3분) 인증 + **필수 약관 동의**
3. **차량번호 입력, 차량 종류와 톤급 선택**: 일반 카고(25톤) / 트랙터(추레라)(25톤) / 워킹 덤프(워킹카)(25톤) / 덤프트럭(25톤) / 기타(직접 입력 칸)로 한정

5. **본사(사측) 심사**: 서류·사진을 대조하고 차량번호 기반 지역 인증. 나머지 대조 설계는 사용자가 추후 공지

7. 가입한 **휴대폰 번호와 비밀번호로 다시 로그인** → 서버가 로그인 정보를 인증하면 **홈 화면(로비)** 으로 이동

1. D01: 물량·품목·차종·상/하차 날짜(당착 또는 다음날 도착) 필수. 단가는 건당 또는 kg당, 부가세는 항상 별도.
2. D02: 차주가 고르면 즉시 확정, 확정 즉시 화주에게 배정 알림.
3. D03: 시간이 겹치는 다건 선택은 막지 않고, 이유 없이 못 지키면 패널티. 하루 수락 건수 상한을 둔다.
4. D04: 배차일 전날 15시가 취소 기준. 수락 후 15시 이후 취소 불가, 과도·사유 불명 취소는 패널티. 취소된 일감은 다시 목록에 올리고, 잡힘·취소 알림을 건마다 화주에게 보낸다.
5. D06: 화주에게 차주 이름·차량번호·차종·톤수·별점 공개. 연락처는 서로 비공개. 매칭 알림에 차량번호·특이사항 전달.
6. D15: 차주 가입 흐름을 새로 정함(3절). 필수 서류는 사업자등록증·통장 사본·운전면허증.
7. D16: 인증번호 3분 확정. 반려 시 사유와 고객센터 문의 안내. 화주는 화주 전용 앱으로 따로 만들 예정(흐름은 추후).
8. 웹 베타 계정·데이터는 앱 출시 때 이어 쓰지 않는다. Firebase 프로젝트는 박재영 계정으로 만들 예정.

확인이 필요한 사항(답을 받기 전까지 구현하지 않음):

- “하루에 4건 이상 수락 못하게”가 하루 최대 3건인지 4건인지, ‘하루’가 상차일 기준인지 수락한 날 기준인지
- ‘배차일’이 상차일인지, 당일 배차 오더의 취소 기한
- 차주 가입에서 이름·비밀번호를 정하는 단계, 화물운송종사자격증·사업자등록증 항목 입력(자동 입력)을 뺀 것인지, 전자세금계산서 전용 이메일을 받는 위치
- 반려 후 재제출 가능 여부
- 화주 전용 앱을 같은 Flutter 코드(`app/`) 안에서 만드는지, 별도 프로젝트인지(현재 방침은 하나의 `app/`)
- 차주 화면 이름: 사용자 답의 ‘오더 찾기’와 문서의 ‘일감 목록’ 탭이 같은 화면인지
