## 1. 서비스 정의와 범위

팜카고는 화주가 올린 운송 일거리를 사업자·지역 인증 절차를 거친 차주가 선택하여 운행하도록 연결하는 운송 알선 앱이다.

- 화주 가치: 운송에 신경을 덜 쓰게 해서, 공장주와의 커뮤니케이션에 더 집중할 수 있도록 업무 부담을 덜어준다.
- 차주 가치: 안정적인 일감과, 동선 최소화·최적화로 운송 부가 비용(톨비·기름값 등)을 줄이고 이득을 키우는 것을 목표로 한다. 차주가 원하는 동선의 일감을 고를 수 있게 한다. 자동 경로 최적화의 구현 방식과 절감액은 아직 정하지 않았다.
- 초기 기능: **화주·차주 입력 → DB 저장 → 화주 간 일감 비공개 → 게시글 형식 일감 목록 → 차주 선택·운행**.
- 화주 홈은 배차 작성과 나의 배차로 연결되며, 본인 일감을 확인·수정하는 방향이다.
- 차주 앱은 홈과 **‘오더 찾기’ 탭**(일감 목록)으로 나눈다. 홈에는 추천 맞춤 오더를 두고, **‘오더 찾기’ 탭에서 일감을 게시글 형식으로 쭉 나열**한다(사용자 결정 2026-11-04, 탭 이름은 2026-11-05 결정. Flutter 코드의 탭 이름은 아직 ‘일감 목록’). 추천 기준(별점·동선 반영 여부)은 아직 정하지 않았다.
- 운영·인증·증빙·제재·혜택은 확인된 요구로 관리하되 세부 방식과 구현 순서는 구체화해야 한다. 운영에는 변수·문제 발생 시 고객센터(전화·카카오톡)가 해당 화주·차주에게 전화로 전후 사실을 확인하고 민원을 처리하는 방식이 포함된다.
- 서비스 AI(OCR 포함)는 기본 틀 구현 뒤 검토한다. 품목은 자주 쓰는 목록(소맥피·단백피·대두·대두박·팜박·옥수수)에서 고르고 없으면 직접 입력한다(D13, 사용자 결정 2026-11-05). 개발 도구로서의 AI 사용과 구분한다. 가입 서류의 사진 자동 읽기(OCR)는 쓰지 않고 본사가 사진을 직접 확인한다(D08, 사용자 결정 2026-11-05).
- 장기 공장·창고 확장: **공장의 원료 발주 → 화주 원료 접수·창고 발주 명령 → 운영 측 조달 → 운송 연결**. **앱 스토어 출시 후 운영이 안정되면** 시작하고, 앱은 공장 발주 접수·창고 발주 명령·원료 조달 관리·운송 오더 자동 연결을 맡는다. 나중에는 팜카고가 하나의 화주가 되어 앱으로 바로 구매하는 서비스를 열 예정이다(D11, 사용자 결정 2026-11-10). 조달 책임과 공장·창고 계정은 추후 결정한다.

## 2. 결정 상태

| D04 | 수정·취소 | 나의 배차에서 수정. **배차일**은 차주가 배차 수락을 누른 날, **상차일**은 물건을 트럭에 싣는 날(보통 배차 다음날). **취소 기준은 상차일 전날 15시**(예: 목요일 상차는 수요일 15시 전까지만 취소). **당일 배차 오더(수락한 날 바로 상차)는 당일 오전 9시까지** 취소 가능. 한번 수락하면 이 시각 이후에는 화주·차주 모두 취소 불가. 시각 전이라도 취소 사유가 불명확하거나 취소가 과도하면 패널티. 취소된 일감은 차주의 ‘오더 찾기’에 다시 올림. 차주가 배차를 잡으면 ‘배차가 잡혔다’, 취소하면 ‘배차가 취소되었다’ 알림을 건마다 화주에게 보냄. **화주가 취소하면 즉시 차주에게 앱 알림**. 차주가 수락한 뒤에도 **화주는 상/하차지·품목 등 조건을 수정할 수 있으나 시간은 수정 불가**, 수정하면 **차주에게 바로 알림**. 화주는 상/하차지를 고칠 때 **변경 사유와 양해 내용을 앱 알림 메시지로 따로 보낼 수 있음**. 화주가 상/하차지를 잘못 입력해 **차주 수락 뒤 바꾼 경우**(**변경 사유 메시지를 미리 보냈더라도**)와 **차종을 잘못 입력한 경우**에는 차주가 **패널티 없이 배차 거절** 가능. 그 밖의 거절은 패널티로 **오더 수락 기능 정지**이며 **D14 경고 1회로 셈**. 정지 기간은 **D14 제재 단계 그대로**(1회 1영업일·2회 7영업일·3회 30영업일), 1회 정지는 **정지된 시각부터 24시간**(일요일에 걸쳐도 그대로 24시간), 7·30영업일 정지도 **정지 시각 기준**(예: 월 14시 정지 → 7영업일 뒤 14시)(사용자 결정 2026-11-04·05·11·12) | — |

## 3. 가입·로그인 초안(D15·D16)

옵시디언 `14 회원가입과 인증`의 ‘10/31 작성한 회원가입 절차 초안’을 구현 기준으로 옮겼다. 더 운반 영상에서 관찰한 절차와 구분한다. 구현 상태는 Flutter 데모(샘플 데이터·시연) 기준이다.

| 단계 | 초안 | Flutter 데모 구현 상태 |
|---|---|---|
| 최초 진입 | 이용 권한 허용 → 로그인·회원가입 로비 | 구현. 카메라·사진·위치·알림·전화 5종을 안내(사용자 결정 2026-11-04). 사유 문구는 임시이며 실제 권한 요청은 하지 않음 |
| 로그인 | 휴대폰 번호(아이디)·비밀번호, 뒤로 가기, ‘비밀번호를 잊으셨나요?’, ‘혹시 회원이 아니신가요?’. **이메일은 쓰지 않음**(사용자 결정 2026-11-04; 옵시디언 초안은 이메일 로그인) | 구현(샘플 데이터 대조). 숫자 11자리만 입력됨 |

### 차주 회원가입 흐름 — 사용자 결정 2026-11-04(2차)

2. **이름·휴대폰 번호 입력** → 문자 인증번호(유효 시간 3분) 인증 + **필수 약관 동의**

6. **본사(사측) 심사**: 서류·사진을 대조하고 차량번호 기반 지역 인증. 나머지 대조 설계는 사용자가 추후 공지

## 4. 구현에 임의로 넣지 않을 내용

- 수수료율은 **4%**이고 차주가 받는 운송비 안에서 떼며, 금액은 1원 미만 반올림한다(D09, 사용자 결정 2026-11-09). 영상의 ‘2%’는 쓰지 않는다. 4%는 부가세를 포함한 운송비에 매긴다(2026-11-09). 취소 기준 ‘상차일 전날 15시, 당일 배차는 당일 9시’와 하루 최대 3건(상차일 기준)은 사용자가 확정했다(D03·D04, 2026-11-04·05). ‘kg당 19원’은 예시이므로 기본값으로 넣지 않는다.
- 하루 수락 상한·취소 패널티가 정해졌다고 해서 패널티 내용(D14)을 임의로 정하지 않는다.
- 경고·정지 단계는 사용자가 정했다(D14, 2026-11-05). 블랙리스트 추가는 대표이사 승인이 필요하므로 **자동으로 블랙리스트에 올리지 않는다**. 블랙리스트에 오른 휴대폰 번호는 대표이사 승인으로 해제되기 전까지 다시 가입할 수 없다(2026-11-11).
- 화주에게는 패널티를 두지 않는다(2026-11-11). 사업 규모가 커지면 정할 예정이므로 화주 패널티를 임의로 만들지 않는다.
- 서버 접수 순 단일 선점은 확정 방향이다. 별점 혜택은 수수료 감면으로 정했으므로(D17, 2026-11-05) 별점으로 선점 순서·선택 가능 시간·대기 순위를 바꾸지 않으며, 이미 완료된 선점도 바꾸지 않는다. 감면은 상위 5% 1%p(수수료 3%), 상위 10% 0.5%p(수수료 3.5%)로 정했고 최소 차주 수 없이 시작 때부터 적용한다(2026-11-09). 5%·10% 인원은 올림해 최소 1명은 감면한다(2026-11-09).
- 약 6~7가지 일거리 언급을 화면 고정 게시 건수·필드 수로 바꾸지 않는다.
- 차주 필수 서류(사업자등록증·통장 사본·운전면허증)는 사용자가 정했다(D15, 2026-11-04). 더 운반의 3영업일 심사·알림톡은 팜카고 정책으로 그대로 채택하지 않는다.
- 지역 인증은 차량번호와 업로드 서류·사진의 사측 대조로 이해한다. GPS 수집·위치 권한 요청으로 임의 확대하지 않는다.
- 배차·취소·증빙 알림은 앱 푸시와 카카오 알림톡으로 보내기로 했다(D02, 2026-11-11). 알림톡은 발송 업체·템플릿 심사·비용을 정한 뒤 테스트와 운영 발송을 나눠 연결하며, 카카오톡 고객센터 상담 대화를 자동 수집하거나 메시지를 임의로 보내는 기능으로 확대하지 않는다. 고객센터의 연락 상대는 해당 화주·차주이며 **화주↔차주 연락처는 서로 공개하지 않는다**(D06, 2026-11-04).
- 가입 서류 OCR은 쓰지 않기로 했다(D08). 서비스 AI 도입은 따로 정한다.

- 계근표·하차 서명 인증을 회원가입 제출 서류로 합치지 않는다.
- Firebase Auth 결정을 다른 Firebase 서비스(DB·파일 저장 등) 채택이나 업무 DB 선택으로 확대하지 않는다.
