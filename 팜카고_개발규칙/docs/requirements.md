## 현재 개발 단계 — 2026-11-03 사용자 결정

- 최종 목표는 Android·iOS 스토어에 출시하는 앱이다. 스토어 출시 조건이 까다로워서, 베타 테스트가 끝날 때까지는 **Flutter Web으로 배포해 브라우저에서 테스트**한다.
- 웹과 앱은 **같은 Flutter 코드(`app/`)** 로 만든다. 베타 종료 후 같은 코드를 앱으로 빌드해 출시한다. HTML 데모(`app-demo.html` 등)는 설계·시연 프로토타입이며 제품 코드의 기준이 아니다.
- 단계: ① Flutter Web 개발·내부 테스트 → ② 웹 베타 테스트 → ③ Android·iOS 빌드와 실기기 검증 → ④ 스토어 출시. ②의 배포 위치는 GitHub Pages(`https://magician-park.github.io/FarmCargo/`)로 정했다. GitHub Pages는 정적 파일만 제공하므로 서버·DB가 필요한 기능을 실제로 쓰는 베타 테스트는 별도 서버를 정한 뒤에 가능하다. ②의 대상·기간과 ③·④의 일정은 아직 정하지 않았다.
- 웹에서 통과한 것이 앱에서도 동작한다고 보장하지 않는다. 카메라·사진·위치·푸시·권한·파일 저장·보안 저장소 같은 기능은 앱 단계에서 다시 검증한다.
- 아래의 ‘앱’은 제품 요구사항을 지칭한다. 실제 서버·DB가 없는 동작은 합성 데이터·시연으로 구분한다.
- 공통 규칙의 기준은 저장소 루트 [AGENTS.md](../../AGENTS.md)다.

## 1. 서비스 정의와 범위

팜카고는 화주가 올린 운송 일거리를 인증된 차주가 선택하여 운행하도록 연결하는 운송 알선 앱이다.

- 화주 가치: 운송에 신경을 덜 쓰도록 한다.
- 차주 가치: 안정적 일감과 운송 부가 비용(톨비·기름값 등) 감소를 지향한다. 비용 절감 방식·금액은 아직 정하지 않았다.
- 초기 기능: **화주·차주 입력 → DB 저장 → 화주 간 일감 비공개 → 게시글 형식 일감 목록 → 차주 선택·운행**.
- 화주 홈은 배차 작성과 나의 배차로 연결되며, 본인 일감을 확인·수정하는 방향이다.
- 운영·인증·증빙·제재·혜택은 확인된 요구로 관리하되 세부 방식과 구현 순서는 구체화해야 한다.
- 서비스 AI·자주 쓰는 품목 선택지는 기본 틀 구현 뒤 검토한다. 개발 도구로서의 AI 사용과 구분한다.
- 장기 공장 확장: **공장의 원료 발주 → 화주 원료 접수 → 운영 측 조달 → 운송 연결**. 실제 앱 기능·조달 책임·시기는 추후 결정한다.

## 2. 결정 상태

ID는 Obsidian 결정 기록과 대응한다. ‘방향 확인’은 세부 정책 전체가 확정됐다는 뜻이 아니다.

| ID | 항목 | 현재 기준 | 남은 결정 |
|---|---|---|---|
| D01 | 입력 정보 | 주소·지역·상하차지·품목·단가·상차 시간대 등 | 물량·차종·날짜 등의 필수 여부, 형식·단위 |
| D02 | 수락 확정 | 선택된 일감은 가용 목록에서 제외하는 방향 | 즉시 확정인지 추가 승인인지 |
| D03 | 동시 선택·선점 | 먼저 선택 우선 방향 | 동시 요청 판정, 별점 우선순위와의 관계 |
| D04 | 수정·취소 | 나의 배차에서 수정. 전날 오후 3시 취소는 예시 | 실제 기한·수락 후 변경·취소·재공개 |
| D05 | 운송 증빙 | 상·하차지 계근표. 하차지 계근표 없으면 서명으로 인증 | 서명자·첨부·검토·보관·열람 |
| D06 | 정보 공개 | 화주 간 일감 비공개. 차종 표기는 워킹·덤프·카고 | 나머지 차주·차량 정보 공개 범위 |
| D07 | 고객센터 | 차주가 배정받은 일거리의 상·하차 장소·시간을 카카오톡 등에 전달하면 직원이 전화 확인 | 확인 상대·시점·상황별 절차 |
| D08 | 서비스 AI | 기본 틀 구현 뒤 검토 | 도입 범위·OCR 의도·자동화 대상 |
| D09 | 수수료·정산 | 앱 자체·일감별·총매출 기준 등 차감 방식을 앱 제작자가 결정 | 실제 방식·요율·부담자·세금계산서 |
| D10 | 운영 인력 | D07 전화 확인을 맡는 직원이 있는 방식 | 담당자·인원·시간·처리 기록·비용 |
| D11 | 초기·장기 경계 | 초기 운송 시스템, 장기 공장 영역 확장 예정 | 장기 기능·책임·일정 |
| D12 | 공동 책임 | 개발·현장 역할 구상 있음 | 개발비·운영비·보상·권한 분담 |
| D13 | 품목 입력 | 초기 직접 입력 | 표기·원산지 구분, 이후 선택지 |
| D14 | 경고·제재 | 경고 2회 시 앱 사용 제한, 블랙리스트 선정 | 제한 일수·사유·누적·선정·해제·검토 절차 |
| D15 | 가입·접근 인증 | 사업자 인증·지역 인증을 거친 차주만 받음 | 확인 방법·증빙·검토자·심사 중 접근 범위 |
| D16 | 가입 서류 보완 | 더 운반 제출·승인 대기 화면을 참고 | 팜카고 서류 범위·반려·재제출·알림·보관 |
| D17 | 리뷰·우선순위 | 화주가 차주를 별점 리뷰하고 우선순위 혜택 제공 | 산정·적용·먼저 선택 우선과의 관계 |
| D18 | 수수료 혜택 | 자주 쓰거나 운송을 잘하는 이용자에게 간헐적 면제·할인 | 실적 기준·대상·주기·할인 폭 |

## 3. 구현에 임의로 넣지 않을 내용

- 취소 기한 ‘전날 오후 3시’, 수수료 ‘2%’를 확정 기본값으로 넣지 않는다.
- 경고 2회라는 방향으로 제한 기간·영구 정지·자동 블랙리스트까지 확정하지 않는다.
- ‘먼저 선택 우선’과 ‘별점 우선순위 혜택’의 충돌을 임의 알고리즘으로 해결하지 않는다.
- 약 6~7가지 일거리 언급을 화면 고정 게시 건수·필드 수로 바꾸지 않는다.
- 더 운반의 3종 서류·3영업일·알림톡을 팜카고 정책으로 그대로 채택하지 않는다.
- 지역 인증을 GPS 수집·권한 요청으로 임의 해석하지 않는다.
- 카카오톡 고객센터를 자동 수집·메시지 발송·API 연동 요구로 확대하지 않는다.
- 계근표·하차 서명 인증을 회원가입 제출 서류로 합치지 않는다.
- 선택된 일감을 가용 목록에서 빼는 것을 원본 데이터 삭제로 구현하지 않는다.
- 공장 발주·조달 자동화를 초기 기능에 추가하거나 4주 개발·3건 테스트를 합의 일정으로 쓰지 않는다.

## 4. 근거와 유지 방법

현재 로컬 Obsidian 기준 문서:

- `E:/[Obsidian] FarmCargo/팜카고/04 결정사항/10 미정 사항과 결정 기록.md`
- `E:/[Obsidian] FarmCargo/팜카고/05 통화 근거/11 통합 근거 기록.md`
- `E:/[Obsidian] FarmCargo/팜카고/06 변경 기록/18 변경·보관 기록.md`

이 파일은 2026-11-03에 확인한 문서의 현재 기준을 옮긴 스냅샷이다. 이후 사용자 결정이 있으면 관련 ID·영향·확인일을 갱신한다. 과거 발언이 현재 요구보다 우선하지 않는다. 근거 파일을 읽을 수 없으면 확인 가능한 범위를 밝히고, 최신 결정 확인이 필요한 작업만 질문한다.

새 결정 기록 형식: **확인일 / 관련 ID / 질문 / 사용자 답변 / 변경 범위 / 남은 설계**.
